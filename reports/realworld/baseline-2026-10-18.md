excluded from the retained report directory before recording this baseline.

its common fork/exec cost is included in startup/whole-process wall time.

Node has N worker threads plus its main coordinator. Go and Badger set runtime
parallelism to N, so this sweep is consumer count, not a strict equal total CPU
cap. Structured-clone vs reference transfer and pool/task lifecycle differences
are explicitly documented. The pipeline shows useful parallel work; the light
messaging case also makes coordination costs visible.

Startup, compilation, preparation, whole-process duration, throughput and peak
RSS are separate dashboard controls. Peak RSS includes compiler/JIT, fixtures,
all threads and every warmup/sample. Preparation compares different products
(Badger front-end → saved MIR vs Go cached native build); Badger source-launch
compilation is also captured separately, and Node has no separate compile value.

This is the first complete historical point. Future matching-cohort runs extend
the series; no historical measurements have been fabricated.
