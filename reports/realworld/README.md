# Badger / Go / Node.js / Java benchmark history

Open [`index.html`](index.html) for the latest head-to-head charts and historical
series. Raw stamped evidence is retained under [`runs/`](runs/). The dashboard is
an offline file generated by the Badger program
[`bench/realworld/report.bdg`](../../bench/realworld/report.bdg).

The [Java-inclusive baseline](java-baseline-2026-10-18.md) records the latest
four-language run, validation and JVM timing/memory boundaries.

The [initial 2026-10-18 baseline](baseline-2026-10-18.md) records validation,
representative results, noisy cells and reproduction details for the original
three-language suite. The latest dashboard also supports Java; its four-language
cohort preserves this original evidence separately.

The [suite guide](../../bench/realworld/README.md) defines the six workload
contracts, measurement boundaries, comparison limits, and reproduction commands.
Each report carries its own exact source revision/hashes and tool identities;
a later commit that only adds evidence does not change the measured revision.
The series starts with a single baseline point; future compatible runs extend it.

```sh
# Follow bench/realworld/README.md for the one-time pinned Gson setup.
# Rebuild Badger at the revision to measure, then add a new stamped report:
cargo build --release --locked -p badger_cli
python3 bench/realworld/run.py

# Rebuild HTML from all retained reports, without rerunning workloads:
target/release/badger run --release bench/realworld/report.bdg -- \
    reports/realworld/runs reports/realworld/index.html
```

Comparisons default to the latest complete non-smoke report. History connects
only runs with matching input/workload/harness/configuration/machine/control-
runtime identities. Compiler revision is intentionally allowed to change.
Smoke and failed runs are counted but excluded from performance charts.

Preparation means different products: Badger front-end → saved MIR and Go cached
native build, plus Java javac bytecode classes. Java JIT stays in
startup/first/warm timings; the default short warmup does not prove steady state.
The workload runs from optimized Badger source; its launch
compilation is also charted separately. Node has no invented separate compile
measurement. Memory means whole-process peak RSS, including compilation/JIT and
all threads/iterations. These are bounded batch applications, not HTTP/database
latency or durable integration correctness benchmarks.
